过去三个月，我把主力开发工作流切到了 AI 编程工具上，Claude Code、Cursor 和 GitHub Copilot 三个都用真实的独立开发项目跑过。这篇不是参数对比表，而是三个月后还留在我的工作流里的东西。

先说结论：三个工具我最后是"分工"使用，而不是二选一。

Cursor 我用在"探索式开发"。它的 Composer 模式适合那种"我还不知道代码会长什么样"的阶段：丢给它一个目录结构和一段需求描述，让它出初版骨架，然后我在它的基础上改。对我这种非科班出身、靠兴趣写代码的人来说，最大的价值是能把"我大概想要什么"快速变成"我可以看到的东西"。缺点也明显：项目一大，它的上下文管理会开始失忆，改 A 文件忘了 B 文件里的约定。

Claude Code 我用在"有明确边界的任务"。比如"给这个模块补齐错误处理""把这个函数重构成可测试的结构"，它的终端形态天然适合这类一次性、有清晰完成标准的活。独立开发里最典型的场景是：周末想到一个小功能，写好验收标准扔给它，我去陪家人，回来看 diff。三个月下来它在长上下文和"记住项目约定"上确实比另外两家稳。但它是助理不是司机，你要是把方向盘完全交给它，它会非常自信地把你带沟里。

Copilot 现在的角色退化成了"编辑器内的自动补全"，负责那些不值得动用前两者的重复劳动：写测试样例数据、补样板代码、写正则。它响应快、便宜、无感，这个定位它做得很好。

给同样想上车的独立开发者的三个建议：第一，先想清楚自己的任务类型再选工具，探索式任务和边界清晰的任务是两种物种，别指望一个工具通吃；第二，所有 AI 生成的代码必须过测试再进主干，这条纪律省下的 debug 时间超过你想象；第三，把提示词和项目约定沉淀成仓库里的文档（比如 CLAUDE.md 和 rules 文件），工具换了一茬又一茬，这些沉淀是跟着你走的。

另外一个小体会：AI 工具越强，"描述需求的能力"越是稀缺。我给我的产品写需求说明的时间，已经从"随便两行"变成了认真写半天。这不是浪费，这是把过去花在 debug 上的时间前置了。工具会继续换代，把需求写清楚这件事的能力，是自己的。
